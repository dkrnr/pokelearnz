# PokeLearn processing and storage

This describes the `backend/hardening` branch; it has not been deployed. It is a technical disclosure, not a claim that provider retention has been audited or that the app is certified for unsupervised children.

- The grown-up gate enables online voice/questions on this device. Microphone permission is also requested by the browser. The gate is arithmetic and the server receives a client consent assertion; neither authenticates a parent. Sound begins off and captions remain available.
- Netlify hosts the page and proxies functions. Typed questions are checked on the server for detected private/sensitive content before OpenRouter. Recorded voice is sent to Valsea for transcription; permitted transcribed text is checked before OpenRouter. Voice can already contain identifying or background speech. The app cannot redact it before upload or erase a copy already received by a provider.
- OpenRouter selects a host for an explicit free model; no free-router is used. Requests require no-data-collection and zero-retention routing flags and zero-price endpoints. Those constraints can produce no eligible endpoint. They express required routing policy, not independently verified provider behavior. Valsea and Netlify retention/logging policies remain unverified.
- Questions, transcripts, answers and recordings are not persisted by application code or cached by the service worker. They exist transiently in browser/server memory during processing. Stopping, Sleep and closing activities release microphone tracks and attempt cancellation; cancelling a request is not a guarantee that remote processing has ceased.
- Application logs contain only error codes, rounded latency and the selected model ID. No questions, transcripts, audio, headers, raw diagnostics, keys, raw IPs or answers are logged by application code. Platform access logs and provider logs remain outside this guarantee.
- Netlify Blobs quota records contain aggregate upstream-attempt counts and daily HMAC-salted IP hashes with minute-window counts. They are pseudonymous rate-limit data, not anonymous data. Hashes change daily; a private salt is required. Old records are cleaned on later activity on a best-effort basis; there is no automatic expiration guarantee. The local memory limiter loses counts on restart and is not used for deployed URLs.
- Device storage holds consent, language and optional buddy/recent choices. Questions and progress/reward counters are not stored. The public offline cache holds the shell, authored lessons and visited sprite images. Sprite payload caching has a 12 MiB limit plus a small size index. jsDelivr receives image-request metadata/IP, never question or voice payloads from this app.
- “Clear device data” clears these device choices/permission and visited sprite caches. It does not clear server quotas or delete Netlify/Valsea/OpenRouter/downstream logs. Withdrawing consent prevents new app requests; it cannot retract already sent data.
- Moderation/privacy detection uses regex and reading/length checks. It misses some disguised or multilingual content and can reject harmless content. Transcription can invent/mishear words; confidence checks only apply when the provider supplies confidence metadata. No human transcript-confirmation step is added in this pass. Authored offline activities avoid provider uploads.

Actual device permissions, provider policies, screen-reader use and SI/TA language safety need further review. No analytics, advertisements, notifications or engagement tracking are introduced by this branch.
